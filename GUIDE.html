01 What this project is

The first machine learning algorithm, written by hand.

You predict the price of a used car from its mileage. The model is a straight line. You do not solve for that line with a formula. You start with a line that is wrong, measure how wrong it is, and step it downhill until it stops improving. That loop is gradient descent, and every neural network in the branch is the same loop with more parameters.

The project proves three things about you. You can turn a written formula into working code. You understand that training and prediction are two separate programs with a saved model between them. You can explain why the algorithm converges instead of quoting a library that hid the work.

Where it sits

One feature, one line, two parameters. Next comes dslr, which is the same descent on many features with a sigmoid on top. Then multilayer-perceptron, which stacks those into layers. Learn the loop properly here and the rest is bookkeeping.

02 The math

Four steps: a guess, a cost, a gradient, a step. Everything else is detail.

The hypothesis

estimatePrice(mileage) = θ₀ + (θ₁ × mileage)

The subject writes it exactly this way, so the code must too. θ₀ is the price of a car with zero mileage. θ₁ is the price lost per kilometre, so it must come out negative.

The cost

How wrong is a given line? Take every car, measure the gap between the prediction and the real price, square it so that positive and negative gaps cannot cancel out, and average.

J(θ₀, θ₁) = 1/(2m) ∑i=0..m-1 ( estimatePrice(xi) − yi )2

The subject never names this function, but it is the one the given formulas differentiate. The 2 in the denominator exists only so it cancels the 2 that the power rule produces in the next step. It changes nothing about where the minimum sits.

The gradient

Differentiate the cost with respect to each parameter. The chain rule gives an outer derivative of 2(error) and an inner derivative of 1 for θ₀ and xi for θ₁.

∂J/∂θ₀ = 1/m ∑ ( estimatePrice(xi) − yi )
∂J/∂θ₁ = 1/m ∑ ( estimatePrice(xi) − yi ) × xi

These two lines are the subject's formulas with the learning rate removed. That is the whole reason the subject looks the way it does.

The step

tmpθ₀ = learningRate × ∂J/∂θ₀
tmpθ₁ = learningRate × ∂J/∂θ₁

θ₀ := θ₀ − tmpθ₀
θ₁ := θ₁ − tmpθ₁

The subject gives you the two tmp lines and leaves the subtraction implied. You move against the gradient, because the gradient points uphill. Both tmp values must be computed from the same old thetas before either theta is overwritten. That is what "simultaneously update" means, and it is the single most common failure at this eval.

Why standardise the feature

Mileage runs to 240000. Price runs to 8290. The cost surface is therefore a valley that is roughly sixty billion times steeper in one direction than the other. Gradient descent is stable only while the learning rate stays under 2/λmax, where λ are the eigenvalues of the Hessian (1/m)XᵀX.

Featureλ maxλ minCondition numberLargest stable learning rate
Raw mileage1.2873e100.20666.23e101.55e-10
Standardised1.01.01.02.0

Standardising turns the valley into a perfect bowl, so the condition number is exactly 1 and a learning rate of 0.1 is comfortable. Replace the feature with its z-score:

zi = ( xi − μ ) / σ    with μ = 101066.25, σ = 51565.19

Train y = a + b·z, then substitute z back to recover the raw-unit line the subject asked for:

y = a + b(x − μ)/σ = ( a − bμ/σ ) + ( b/σ )x

θ₀ = a − bμ/σ     θ₁ = b/σ

Those two identities are train.py:38-39 verbatim. The saved model is therefore in raw kilometres, and predict.py evaluates the subject's hypothesis with no rescaling anywhere.

Proof that it converged

A single-feature least squares problem has a closed form. Compute it and compare.

θ₁ = ∑(x−x̄)(y−ȳ) / ∑(x−x̄)2     θ₀ = ȳ − θ₁x̄

Closed form: θ₀ = 8499.599650, θ₁ = -0.021448964. Gradient descent after 2000 iterations: θ₀ = 8499.599650, θ₁ = -0.021448964. Identical to nine decimals. The descent reached the exact optimum, and you can say so with a number rather than a feeling.

The contract between the two programs

train.py writes one CSV row: theta0,theta1. predict.py reads it, and falls back to (0.0, 0.0) when the file is missing. That fallback is a subject requirement, not a convenience. It is also why the two programs never import each other's state: the file is the entire interface.

04 Walkthrough

The training loop, line by line, as it exists in this repository.

Step 1. Load the data

def load_data(path):
    xs, ys = [], []
    with open(path) as f:
        for row in csv.DictReader(f):
            xs.append(float(row['km']))
            ys.append(float(row['price']))
    return xs, ys
train.py:15-21

csv.DictReader reads by column name, so the code does not break if the column order changes. Everything becomes float immediately, because integer division would silently truncate the gradients later.

Step 2. Standardise the feature

    m = len(xs)
    mean = sum(xs) / m
    std = (sum((x - mean) ** 2 for x in xs) / m) ** 0.5
    xn = [(x - mean) / std for x in xs]           # standardised feature
train.py:25-28

This is the population standard deviation, dividing by m rather than m-1. Either works here, because the value is only a scaling constant that gets folded back out at the end. Note ** 0.5 instead of math.sqrt, which keeps the file free of imports that an evaluator might question.

Step 3. Descend

    t0 = t1 = 0.0
    for _ in range(iters):
        errs = [(t0 + t1 * xn[i]) - ys[i] for i in range(m)]
        g0 = sum(errs) / m
        g1 = sum(errs[i] * xn[i] for i in range(m)) / m
        t0, t1 = t0 - lr * g0, t1 - lr * g1        # simultaneous update
train.py:30-35

Read this against the subject formula and the mapping is exact. errs is estimatePrice(x) - price. g0 and g1 are the two sums divided by m. Multiplying by lr gives the subject's tmpθ values, and the tuple assignment subtracts both at once.

Why the tuple assignment matters

Python evaluates the entire right-hand side before it binds anything on the left. So t1 on the right is still the old t1 when t0 is being computed. Split it into two statements and the second update uses a theta that already moved: a different, wrong algorithm. Both errs and the two gradients are also computed once per iteration from the same thetas, which is the same rule applied one level up.

Step 4. Fold the scaling back

    # fold standardisation back into raw-scale thetas
    theta1 = t1 / std
    theta0 = t0 - t1 * mean / std
    return theta0, theta1
train.py:37-40

The algebra from section 2. After this line the standardisation has left no trace: the returned pair describes a line in raw kilometres, and nothing downstream needs to know that training happened in z-scores.

Step 5. Save, then predict

def load_thetas(path=THETAS_FILE):

07 Eval defense

Answer out loud first. Then open the block and compare.

The evaluation sheet checks three things: no library did the work, the specified hypothesis is used, and the specified training function is used. Most questions below are a peer probing whether you actually understand what you typed.

Walk me through what happens in one iteration of the loop.

Compute the prediction for all 24 cars with the current thetas. Subtract the real price to get 24 errors. Average the errors to get the gradient for θ₀, and average the errors weighted by mileage to get the gradient for θ₁. Multiply both by the learning rate and subtract them from the current thetas at the same time. The line has moved slightly downhill on the cost surface.

Why do you subtract the tmp values instead of adding them?

The gradient points in the direction of steepest increase of the cost. We want the cost to decrease, so we move the opposite way. Adding would climb the hill and the parameters would run away to infinity, which you can demonstrate in the playground by making the learning rate large enough to overshoot.

What does "simultaneously update" mean, and what breaks without it?

Both gradients must be computed from the same pair of thetas, and both thetas updated afterwards. If you write t0 = t0 - lr*g0 and then recompute the error using the new t0 before updating t1, you are no longer descending the gradient of J. It usually still converges on this dataset, which is exactly why it is a dangerous bug: it looks fine and it is the wrong algorithm. The code avoids it with the tuple assignment at train.py:35, because Python evaluates the whole right side first.

The subject's formula uses raw mileage. Your code standardises. Is that still the specified training function?

Yes, and this is the question to prepare hardest. Three points. First, the update rule at train.py:32-35 is the subject's formula character for character, applied to a feature called xn. Second, standardisation is an affine change of variable, so the cost function has the same unique minimum; only the path taken to reach it changes. Third, train.py:38-39 converts the result back into raw units, so what gets saved and what predict.py evaluates is exactly estimatePrice(mileage) = θ₀ + θ₁ × mileage.

The closing proof: the closed-form least squares solution for this data is 8499.599650 and -0.021448964, and the descent lands on the same numbers to nine decimals. It found the correct optimum of the stated problem.

Then why not just run the subject's formula on raw mileage?

Because it is numerically unusable here. Mileage is around 1e5, so the θ₁ gradient carries a factor of 1e5 while the θ₀ gradient does not. The Hessian has eigenvalues 1.29e10 and 0.21, a condition number of about 6e10. Gradient descent is stable only below 2/λmax, which is 1.55e-10. At any learning rate that moves θ₀ in reasonable time, θ₁ explodes. Standardising makes both eigenvalues exactly 1, so one learning rate serves both directions.

Show me the algebra that turns the standardised thetas back into raw ones.

Training fits y = a + b·z where z = (x - μ)/σ. Substitute: y = a + b(x - μ)/σ = (a - bμ/σ) + (b/σ)x. Matching that against y = θ₀ + θ₁x gives θ₁ = b/σ and θ₀ = a - bμ/σ, which is what train.py:38-39 computes.

Where does the cost function come from? The subject never writes one.

It is mean squared error with a half in front: J = 1/(2m) ∑(prediction - price)². Differentiating it with respect to θ₀ and θ₁ gives precisely the two sums in the subject. The half exists to cancel the 2 from the power rule, and it has no effect on where the minimum is, only on the scale of the gradient, which the learning rate absorbs anyway.

How do you know 2000 iterations is enough?

Two ways. Empirically, the cost curve is flat long before the end and the thetas stop changing in the printed digits. Analytically, the result matches the closed-form solution to nine decimals, so there is no accuracy left to gain. On a standardised feature with a learning rate of 0.1, the error contracts by a factor of 0.9 per iteration, so after 2000 iterations the remaining error is around 0.92000, which is far below floating point resolution.

What happens if the learning rate is 1.5? Or 2.5?

On the standardised feature the Hessian is the identity, so each iteration multiplies the remaining error by 1 - learningRate and the stability limit is exactly 2. At 1.5 the factor is -0.5, so the fit overshoots the minimum and comes back from the other side each iteration, shrinking as it goes. At 2.5 the factor is -1.5, so every overshoot is larger than the last and the cost climbs without bound. Demonstrate both in the playground rather than describing them.

Why is theta1 negative, and what does its magnitude mean?

Negative because price falls as mileage rises, which is the whole premise of the dataset. The magnitude 0.021449 is a price per kilometre: every extra kilometre costs about 2.1 cents of value, so 100000 km costs roughly 2145. Being able to read a parameter as a quantity in the real units of the problem is what separates understanding the model from running it.

What does theta0 mean on its own?

8499.60 is the model's price for a car with zero kilometres. It is an extrapolation: the cheapest mileage in the data is 22899 km, so no observation supports it directly. It is a parameter of the fitted line, not a claim about new cars.

Is this model any good? Give me a number.

R squared is 0.733, so mileage explains about 73 percent of the variance in price. The RMSE is about 668, on prices averaging 6332, so a typical prediction is off by roughly 10 percent. The fit beats predicting the mean, whose MSE is 1668925, by a factor of nearly four. It is a good simple model and it is obviously not the whole story, since age, model and condition are not in the dataset.

What does predict.py do before training, and why?

It prints 0.00. The subject states that theta0 and theta1 are set to 0 before the training program has run. load_thetas catches FileNotFoundError and returns (0.0, 0.0), so the hypothesis evaluates to zero for any mileage. Demonstrate it by deleting thetas.csv first.

Which libraries did you use, and would any of them count as cheating?

csv for file reading, sys for arguments, os in the test only. No numpy, no pandas, no scikit-learn. The subject explicitly names numpy.polyfit as cheating because it solves the regression for you. Nothing here computes a fit; the arithmetic is +, -, *, / and one ** 0.5 for the standard deviation.

What would you change to support two features instead of one?

Thetas become a vector, the prediction becomes a dot product, and the gradient becomes one averaged sum per feature. The loop structure does not change at all. Standardisation becomes more important rather than less, because features with different units now compete directly. That is exactly the step dslr takes.

Why does the code use ** 0.5 rather than math.sqrt?

They are equivalent for a non-negative float. Using the operator keeps train.py free of a math import, so the file's only imports are csv and sys, and there is nothing for an evaluator to question about what a library might be doing. It is a presentation choice, and worth stating as one.
